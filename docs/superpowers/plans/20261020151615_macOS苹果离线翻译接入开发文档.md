# macOS 苹果离线翻译接入开发文档

> **交接状态：代码实现完成，自动化回归通过；真实语言包下载、断网和 macOS 14 实机验收待完成。**
> 2026-10-20 已按本文完成原生协调器、Dart 服务、设置页、首页和截图链路。下面的复选框只记录当前已有证据；实机结论以第 5 节和验收矩阵为准。本批未提交、推送或发布。

**目标：** 在 macOS 15+ 为小安翻译接入 Apple Translation，让用户手动选择后可在首页和截图翻译中使用系统端侧模型。

**架构：** 保留现有 `TranslationService`、Provider、数据库和主 Flutter 引擎。新增 Dart 苹果服务与 Swift 原生协调器，复用桌面 MethodChannel；通过真实可见的 SwiftUI 宿主取得 `TranslationSession`，先准备语言包，再翻译。

**技术栈：** Flutter / Dart、Riverpod、MethodChannel、AppKit、SwiftUI、Translation。使用系统框架，不新增第三方翻译库。

**规格依据：** 本文第 1～5 节是本次实现契约；原[截图翻译方案第 7 节](../../02_design/20261002225612_macOS截图翻译实施方案.md#7-apple-translation-扩展)为背景，原[实施计划 Task 8](20261002225612_macOS截图翻译实施计划.md#task-8增加-macos-15-苹果端侧翻译)由本文细化。新增用户仍默认百度，本批不实施旧方案中的默认引擎切换。

## 2. Apple API 依据与兼容性

- Apple 的 [WWDC24 接口介绍](https://developer.apple.com/videos/play/wwdc2024/10117/)说明，`TranslationSession` 使用设备端模型；系统已下载的语言包可被应用复用，缺包时由框架征求下载授权；会话依附 SwiftUI view 生命周期，不能作为脱离 view 的永久模型存储。
- [macOS 15 发布说明](https://developer.apple.com/documentation/macos-release-notes/macos-15-release-notes)列出应用内 `TranslationSession` 能力。
- 用 [LanguageAvailability](https://developer.apple.com/documentation/translation/languageavailability)查询语言对，区分 `installed`、`supported`、`unsupported`。`supported` 表示支持但未安装，仍应允许选择服务。
- 本机 Xcode SDK 的 `Translation.swiftinterface` 已核对：`LanguageAvailability`、`TranslationSession` 自 macOS 15.0 可用；`TranslationSession.init(installedSource:target:)` 与 `cancel()` 自 macOS 26.0 可用。统一实现使用 `.translationTask(configuration)`，不以 26+ 方法作为 macOS 15 路径的前提。
- [Apple 系统使用说明](https://support.apple.com/en-gb/guide/mac-help/mchldd8b3c15/27/mac/27)提供系统语言包下载与设备端模式入口。应用仍须查询 API 状态，不能以系统设置中存在菜单代替运行时检测。

以上为官方文档及 SDK 声明核对，不是本应用运行证据。不硬编码 Intel/Apple Silicon 或 Apple Intelligence 开关作为启用条件，也不据此承诺所有硬件可用；记录实际硬件、系统版本、语言查询和实机结果。若官方能力查询不可用或抛错，显示“无法检查苹果翻译，请重试”，保持禁用并提供重试。

## 3. 产品与交互契约

### 3.1 服务选择与持久化

| 条件 | 苹果选项 | 行为 |
| --- | --- | --- |
| Android / iOS / 其他平台 | 延续现状禁用 | 不调用 macOS channel；移动端默认 ML Kit |
| macOS 14 | 禁用 | 显示“需要 macOS 15 或更新版本” |
| macOS 15+，检查中 | 禁用 | 显示“正在检查苹果翻译可用性…” |
| 英文/简中语言对 supported 或 installed | 可选 | 点击只保存 `translation_engine=apple`，不自动下载 |
| 系统返回 unsupported | 禁用 | 显示“此设备暂不支持英文与简体中文离线翻译” |
| 查询异常或 bridge 缺失 | 禁用，可重试 | 不伪装为系统版本太低，不写入新选择 |

保持 `defaultEngineFor(macOS) == 'baidu'`，不自动修改已有偏好。保存的 apple 在暂时不可用或旧系统上仍保留；Provider 对 macOS apple 返回苹果服务，由它明确报不支持，禁止静默转到百度。非 macOS 的遗留 apple 配置仍按原平台默认服务处理。

选中苹果后，设置页展示离线说明；百度凭据区与“测试连接”只在百度选中时展示。切换服务保留凭据。提示首次准备需要联网下载、翻译在设备端进行、语言包由系统管理。不把 Apple 包列入现有 ML Kit 模型页，也不删除系统包。

### 3.2 准备、翻译、取消

1. 用户提交文本或截图 OCR 完成后，固定本次服务和独立 requestId；苹果请求先查实际语言对。
2. 对有效语言对，通过原生可见宿主取得会话并调用 `prepareTranslation()`；即使已安装也按同一入口准备，通常快速完成。
3. 缺包时显示系统确认与下载界面。应用只显示“正在准备苹果离线翻译，请完成系统提示”，不显示编造的百分比，也不弹 ML Kit 下载对话框。
4. 准备完成且请求仍有效，调用同一会话的翻译方法；从此时计算 30 秒翻译超时。
5. 成功后先确认请求有效，再显示译文、保存 `engine=apple` 的历史；准备、取消或失败不写成功历史。
6. 用户取消、切换引擎、开始新截图、关闭截图结果或销毁调用者时，取消对应请求并释放宿主。调用方先使请求失效，再异步取消；晚到结果不能更新 UI 或历史。

首页取消返回 idle 并保留输入；截图取消返回 idle。准备失败显示可重试原因；不能全部折叠为“缺少百度凭据”。新旧请求用唯一 ID 区分，不用裸 `shot-1` 这类会跨控制器生命周期复用的 ID；可复用项目已有 UUID 能力。

### 3.3 原生窗口与截图共存

采用一个轻量、有标题和取消按钮的 AppKit `NSPanel` + `NSHostingController` 宿主；不增加 FlutterEngine，不替换主窗口的 Flutter contentViewController。面板展示真实内容、参与 view 生命周期，禁止透明、零尺寸或离屏宿主。系统下载 UI 附着此宿主。宿主标题为“苹果离线翻译 / Apple Offline Translation”。

准备与实际翻译沿用同一活跃 `.translationTask` 闭包。准备完成后闭包等待对应 `translateText` 请求，不能先结束闭包，再拿已失效会话翻译。完成、取消、失败均关闭宿主并断开回调；不在单例中永久缓存 TranslationSession。

截图新增 preparingTranslation 阶段，沿 `lib/app.dart` 的状态快照传给原位面板。准备期间暂停原位面板的 180 秒自动关闭；对苹果宿主和其系统 sheet 的点击不能被原位面板“点击外部关闭”监听当成取消。其余点击、Esc、重新截图规则保持可用。准备结束恢复既有面板计时策略。完整状态也需覆盖 Flutter 结果页的 switch，尽管当前 macOS 使用原生覆盖面板。

主窗最小化、应用后台、全屏 Space 下都必须实际看到并操作系统授权。单个原生协调器一次只处理一个苹果请求；另一个调用者同时发起时返回 `appleBusy`，不抢占或取消其他调用者的任务。

## 4. Dart / 原生接口契约

### 4.1 复用 MethodChannel

继续使用 `xiaoan_tsl/macos_desktop`，由 `MacDesktopBridge.handle` 分派至新增 `AppleTranslationBridge`；事件通道不变。下面的方法名为本批新契约。

| 方法 | 参数 | 返回 |
| --- | --- | --- |
| `appleTranslationAvailability` | `sourceLanguage`、`targetLanguage` 字符串 | `{status: platformUnsupported\|unsupported\|supported\|installed}` |
| `prepareAppleTranslation` | `requestId`、`sourceLanguage`、`targetLanguage` | 准备完成返回 null；保留该请求的活跃宿主与会话 |
| `translateText` | `requestId`、`text` | `{requestId: String, translatedText: String}`；必须对应已准备请求 |
| `cancelAppleTranslation` | `requestId` | null；不存在或已结束时幂等成功，不能取消别人的请求 |

macOS 14 的 availability 返回 platformUnsupported，其余苹果操作返回 appleUnsupported；不能先创建 15+ 类型再检查版本。`#available` / `@available` 隔离所有相关声明与调用，确认 framework 弱链接和 14.0 启动兼容。

所有调用在原生边界校验字段类型、非空 ID、有效语言和文本长度。统一延续 5000 字符限制；Swift 用与 Dart `String.length` 一致的 UTF-16 计数检查，避免 emoji 边界不一致。不能使用 `?? ""` 将坏参数伪装成正常请求。非法参数返回 appleInvalidArguments；会话阶段或 ID 不匹配返回 appleInvalidRequest。

语言映射使用系统 `supportedLanguages` 的语言值匹配应用代码；`zh` 要求简体中文，不盲目映射为繁体或任意中文变体。`auto` 不发送原生翻译入口，沿用现有 NaturalLanguage 检测得到显式代码。相同语言或同一语言变体间请求依系统判定拒绝，未知代码拒绝；不可硬编码“列表中全部支持”。

### 4.2 Dart 服务与调用方式

新建 `lib/services/translation/apple_translation_service.dart`，包含服务、能力状态、可覆盖的能力 Provider 和类型化异常；不修改 `MacosDesktopService` 接口，避免迫使所有桌面测试替身增加无关方法。

```dart
// 实现既有 TranslationService；下列为新增苹果专用接口的签名约定。
Future<AppleTranslationAvailability> availability({
  required String sourceLanguage, required String targetLanguage,
});
Future<void> prepare({
  required String requestId,
  required String sourceLanguage, required String targetLanguage,
});
Future<void> cancel(String requestId);
```

`engineId == 'apple'`，`requiresMlKitModels == false`。服务的 `translate` 实现兼容既有必填参数，并增加苹果类专用的可选 `String? requestId`：传 ID 时消费已经 prepare 的请求；不传时生成唯一 ID，自行 prepare 再翻译。这使普通 `TranslationService` 调用仍完整可用；两个控制器为区分准备阶段使用显式 ID 路径。不要给通用服务接口和所有测试替身添加苹果专用参数。

服务可注入 MethodChannel 供测试，验证响应形状与 requestId；空译文、错误 ID、通道缺失、PlatformException 都不能返回成功。成功/失败路径清理本请求；取消清理失败不覆盖原始错误。状态从系统重新查询，不在 SQLite 保存“模型已安装”。

### 4.3 超时与生命周期

- 准备阶段独立上限 10 分钟；超时只结束本应用请求并提示准备超时，可重试。不能声称已停止系统后台下载。
- prepare 已完成但 Dart 未继续 translate，原生 30 秒后清理闲置会话，避免调用方销毁留下窗口。
- 实际 translate 由原生执行 30 秒上限；截图控制器现有 30 秒超时只包住准备后的翻译，并在超时时调用 cancel。首页也使用服务的同一原生翻译上限。
- macOS 15 取消靠任务取消、终结等待 continuation、卸载宿主和迟到回调防护；不调用 26+ `session.cancel()`。关闭宿主不能保证取消系统全局语言包下载。
- `FlutterResult` 对每次调用恰好完成一次；prepare 完成、取消、超时、窗口关闭和系统错误竞争时，用统一 finish 入口保护。取消已失效请求、旧计时器触发，均不得释放新请求宿主。
- requestId 绑定调用者；首页与截图不得互相取消。服务切换需使两个业务中的旧请求失效并清理其各自持有的请求。现有“固定服务 + 请求序号”保护继续保留。

### 4.4 错误与展示

新增一个 `AppleTranslationException`，持有稳定错误代码；按 SDK 公共错误与取消结果分类，不解析中文/英文错误字符串。未知系统错误归 appleTranslationFailed，安全日志只留代码及阶段，不记录原文、截图或凭据。

| 原生错误码 | 用户可见行为 |
| --- | --- |
| appleUnsupported | 当前系统不支持苹果离线翻译 |
| appleUnsupportedLanguage | 所选语言组合暂不支持苹果离线翻译 |
| appleCancelled | 取消，回 idle，不保存历史 |
| applePreparationFailed | 语言包准备失败，请检查网络和可用空间后重试 |
| applePreparationTimeout | 语言包准备超时，请稍后重试 |
| appleBusy | 苹果翻译正在处理另一项任务，请稍后重试 |
| appleTimeout | 翻译超时，请重试 |
| appleInvalidArguments / appleInvalidRequest / appleTranslationFailed | 苹果离线翻译失败，请重试；记录安全错误码 |

对语言未安装且断网的情形显示准备失败；不调用百度。磁盘空间不足只在 SDK 能明确区分时细化，不能靠猜测断言原因。Dart 通道异常保留为可追踪失败，不自动转到在线服务。

首页的 `localizedMessage` 实际按枚举选择文案，因此不能只写 `state.message`。添加准备阶段、苹果错误字段/类型并在本地化出口映射。截图的 failure switch、原生 `MainFlutterWindow` 文案和快照解析也要同步；不要只改 Flutter 页面，导致原位面板仍显示通用错误。
