## 1. 实施范围与阶段

首版完成 macOS 14+ 的“全局快捷键 → 框选 → 本地 OCR → 百度翻译 → 截图下方译文”，并允许 Android/iOS 从现有 ML Kit 切换到同一百度服务。

扩展阶段为 macOS 15+ 加入 Apple Translation。它经过独立验证后成为可选离线服务，不因更新自动覆盖用户保存的服务选择。

首版不增加 Rust、后台服务器、通用插件市场、连续屏幕监控或新的历史数据库。其他 API 是选型备选，只有用户选择且确定接入时才增加具体实现。

## 2. 实现分工

| 部分 | 职责与复用方式 |
| --- | --- |
| Flutter 设置页 | 服务选择、凭据输入、连接测试、截图快捷键 |
| TranslationService | 复用现有翻译方法与 engineId；增加是否需要 ML Kit 模型的能力标记 |
| 翻译 Provider | 根据平台和用户配置解析实际服务，测试可覆盖平台与服务 |
| Dio | 复用受控网络客户端，设置超时，不添加原文或密钥日志 |
| macOS 原生桥接 | 注册快捷键、菜单栏、权限、截图/OCR/语言识别及窗口尺寸 |
| 截图控制器 | 管理独立截图会话，调用现有服务，不改写首页输入 |
| Flutter 截图结果页 | 独立展示引擎复用结果页；主引擎负责截图、翻译和历史保存 |
| SQLite | 复用 app_settings 与 translation_records；仅保存普通设置及文本历史 |
| 安全存储 | 使用系统 Keychain/Keystore 保存用户凭据，禁止写到 SQLite |

已有 TranslationModelService 专门用于 ML Kit；不伪装成 API 模型管理器，也不把 Apple 下载状态写入它。

### 2.1 依赖选择

- 继续使用 flutter_riverpod、go_router、sqflite、dio、path_provider。
- macOS 截图/OCR/窗口使用系统 AppKit、ScreenCaptureKit、Vision、NaturalLanguage。
- 快捷键使用原生 RegisterEventHotKey；无需另加快捷键插件，因为原生桥接已是必需部分。
- 密钥使用 flutter_secure_storage，覆盖 Android/iOS/macOS；配置其当前版本所需的平台项并验证。
- 百度开放平台签名使用 crypto。当前锁文件已有该传递依赖，但生产代码直接导入时仍需声明为直接依赖。
- 不使用截图插件代替选区坐标；它可用于参考或早期比较，正式链路保留原生屏幕位置。
- 具体包版本由实施阶段在当前官方 Flutter SDK 下解析，同步 pubspec.lock；本轮不安装。

## 3. 引擎选择与翻译调用契约

### 3.1 平台规则

| 平台 | 无已保存选择时 | 可选服务 | 禁止行为 |
| --- | --- | --- | --- |
| Android/iOS | mlkit | mlkit、baidu | 选择在线服务后仍下载 ML Kit 模型 |
| macOS 14 | baidu，缺凭据时显示配置入口 | baidu | 创建 ML Kit 插件对象或伪造译文 |
| macOS 15+ 首版 | 同 macOS 14 | baidu | 默认调用尚未交付的苹果翻译 |
| macOS 15+ 扩展交付后 | 新用户可默认 apple；已有选择不变 | apple、baidu | 苹果失败时自动上传文字 |

平台判断由可覆盖的 Provider 集中提供，避免在每个页面重复判断。未知服务值恢复为该平台支持的默认值，并提示用户；不静默改成另一家付费服务。

### 3.2 最小接口变化

保留现有 TranslationService.translate 和 engineId，增加 requiresMlKitModels：

~~~dart
// 翻译实现是否需要走现有 ML Kit 模型检查与下载流程。
bool get requiresMlKitModels;
~~~

MlKitTranslationService 返回 true；BaiduTranslationService、AppleTranslationService 和 DemoTranslationService 返回 false。实现了接口的测试替身同步更新。

AppController 在请求开始时固定本次使用的服务实例。仅 requiresMlKitModels 为 true 时读取 translationModelProvider。服务切换增加请求序号，旧结果不得更新 UI 或写入历史。

macOS 语言识别由 NLLanguageRecognizer 完成，返回应用语言代码。低置信度返回 null，遵循现有手动源语言回退；截图业务单独使用固定英文方向与用户确认。

截图控制器复用 translationServiceProvider；它不调用 AppController.setInput，不破坏主窗口中用户正在编辑的文本。macOS 首版可选服务都无需 ML Kit 模型；苹果模型准备由原生苹果服务负责。

### 3.3 语言与结果

应用内部继续使用当前语言代码。各服务在边界映射自己的代码，百度如 ja → jp、ko → kor、fr → fra、es → spa，不能直接使用 ML Kit 枚举限制在线服务。

首次接入需明确映射当前 appLanguages 全部可选语言，并用官方接口支持列表核对。不支持的语言组合在请求前报错。

历史仍使用 engineId，首版值为 mlkit、baidu、demo，扩展增加 apple。历史及首页统一显示相应本地化名称，未知值显示“未知翻译服务”，不得误标为演示或设备端翻译。

截图英文超过现有 5000 字符上限时显示说明，并允许缩小选区；首版不自动分段计费。一般 OCR 换行按文本块整理，保留段落、列表与代码的显式换行，不对全部换行做无条件空格替换。

## 4. 百度接入与凭据

### 4.1 产品类型

默认实施分支是百度翻译开放平台通用文本翻译，凭据为 AppID＋密钥，HTTPS POST 调用：

~~~text
https://fanyi-api.baidu.com/api/trans/vip/translate
sign = MD5(UTF8(appid + 未编码原文 + salt + secret))
请求字段：q、from、to、appid、salt、sign
~~~

salt 使用随机值。先对原文签名，再交给 Dio 做表单编码；响应按 trans_result 的原有顺序组合 dst。

若现有账号实际属于百度智能云，实施前按其当前官方文档确认认证方式和接口，替换本任务的客户端及认证测试。首版只交付用户实际持有的百度产品，不并行维护两套无使用场景的客户端。开放平台额度不能作为智能云额度。

### 4.2 存储与错误

普通设置键：

| 键 | 值与用途 |
| --- | --- |
| translation_engine | mlkit、baidu、apple |
| screenshot_shortcut | 序列化修饰键与物理键，macOS 使用 |
| screenshot_target | 首版固定 zh，便于恢复设置 |
| baidu_product | 实施确认的百度产品类型，不含凭据 |

安全存储保存当前百度产品的必要凭据；设置页显示掩码，编辑及删除有明确反馈。账户总密钥不得内置到公开二进制中，用户在自己设备填写。

测试连接使用固定短句，成功才显示通过，不写入翻译历史。首次点击前说明会产生一次在线请求。鉴权失败、限流、额度不足、网络超时、返回结构错误分别归类；首版不对收费请求做自动重试，用户可手动重试。

任何 Dio 拦截器、异常展示、诊断导出和测试产物不得含密钥或完整原文。在线模式首次使用说明文字将交给当前服务；离线模式没有隐式云端回退。

## 5. macOS 原生桥接与会话

### 5.1 通道

使用一个 MethodChannel：xiaoan_tsl/macos_desktop。通道只有目标平台可调用，非 macOS 返回明确的不支持状态。

| 方向 | 方法 | 数据 |
| --- | --- | --- |
| Dart → Swift | configureShortcut | 修饰键集合与物理键码 |
| Swift → Dart | screenshotShortcutPressed | 只通知触发，不传屏幕内容 |
| Dart → Swift | captureRegion | 会话 requestId |
| Swift → Dart 响应 | captureRegion 结果 | requestId、PNG 字节、displayId、选区坐标、像素尺寸 |
| Dart → Swift | recognizeText | requestId、PNG 字节 |
| Swift → Dart 响应 | OCR 结果 | 文本块内容及顺序；空内容也是正常结果 |
| Dart → Swift | identifyLanguage | 文字；返回标准代码或 null |
| Dart → Swift | showResultWindow | displayId 与选区坐标 |
| Dart → Swift | updateResult | 截图阶段、错误、PNG、原文、译文、主题与语言的展示快照 |
| Dart → Swift | cancelCapture | requestId；关闭选区层并取消过期 OCR |
| Dart → Swift | openScreenCaptureSettings | 打开系统屏幕录制权限页 |

原生错误统一为 permissionDenied、captureCancelled、captureFailed、ocrFailed、shortcutConflict、platformUnsupported；取消不等同失败。请求完成回调每次只执行一次，退出和销毁时清理事件处理器及窗口。

### 5.2 截图流程

- 请求屏幕录制权限；拒绝时给系统设置入口，不反复请求。
- 隐藏现有结果窗，取得各显示器的一次性快照，随后显示覆盖快照的选区面板；避免把选区遮罩截进图片。
- 在用户开始拖拽的显示器内完成选区；起始屏幕之外的拖拽按该屏幕边界裁切。
- 极小选区或空选区直接取消；裁剪 PNG 返回 Dart，随即释放完整屏幕快照。
- Vision OCR 在后台队列运行，主线程只更新选区和结果窗口。
- 整个会话只处理选中的截图，不持续采集后台屏幕。

### 5.3 坐标契约

原生统一使用 macOS 全局 AppKit point 坐标，并明确矩形左下原点；屏幕可能有负坐标。Flutter 不自行假设主屏原点或 1 point = 1 pixel。

原生按 displayId 取得当前屏幕 frame、visibleFrame、backingScaleFactor。裁剪时转换为截图像素坐标并翻转 y 轴；返回像素尺寸独立于窗口布局尺寸。

窗口优先放在选区下方；空间不足时移到上方或屏幕可见区域内，保持“截图在上、译文在下”。长内容在内部滚动。位置计算在原生侧完成，Dart 不复制另一套算法。

### 5.4 主窗口与独立结果窗口（2026-10-12 调整）

主窗口保留当前页面、输入、尺寸和位置；结果窗口独立显示截图、原文、译文及操作。Dock 图标和菜单“打开主窗口”始终唤起主窗口，即使结果窗口仍可见。两者可同时访问。

当前 SDK 的同引擎多视图需要内部开关，因此使用公开 FlutterEngine API 为结果窗口创建展示引擎。该引擎仅启动 `screenshotWindowMain`，不初始化数据库、凭据、翻译服务或全局快捷键。主引擎仍是截图会话、网络请求和历史记录的唯一业务所有者，移动端使用原来的启动流程。

主通道 `updateResult` 传递展示快照；独立通道 `xiaoan_tsl/screenshot_window` 以 `ready` 取得最新快照、以 `update` 接收更新。结果引擎的 `dismiss/reshoot/confirm/retry/configure` 仅转发给主引擎，分别结束会话、重新截图、确认语言、重试或在主窗口打开翻译服务设置。应用语言及浅色、暗色主题随主应用同步。

关闭结果窗口（系统红色按钮、页面关闭或 Esc）清理截图会话、释放 PNG 并恢复主窗口。关闭主窗口只隐藏主页；明确的退出菜单或 Command+Q 才终止应用。结果窗口及展示引擎按需创建并复用，退出时关闭展示引擎。截图前隐藏主页和旧结果，避免捕获自身界面；无选区的捕获错误也通过独立结果窗口展示。

全屏 Spaces、多显示器和完整截图到在线译文的交互仍须分别做实际验收，窗口单测不能替代这些场景。

## 6. 截图状态与界面

状态为 idle → capturing → recognizing → translating → success/error；取消返回 idle。进入新会话、切换服务、关闭结果、取消选区时递增 requestId；晚到的 OCR/API 结果不得显示或写入历史。

只有本次成功且仍有效的请求保存文本历史。保存失败仍展示译文并提示；截图字节始终不写入 translation_records。重试针对当前 OCR 原文，不重新截屏，也不覆盖已有收藏。

结果页显示本次来源服务。按钮使用 Flutter 内置 Icons，颜色从主题取得；中英文界面均有权限、空截图、非英文、缺凭据、限流、模型缺失和取消文案。

设置页隐藏不受当前平台支持的离线模型管理入口；直接进入 /offline-models 时也检查支持性。Android/iOS 即使选在线服务，仍可手动管理自己的 ML Kit 语言包。

## 7. Apple Translation 扩展

macOS 15+ 使用公开 Translation 框架，通过同一原生桥接增加 translateText 和语言可用性检查。AppleTranslationService 仍实现既有 translate 契约，requiresMlKitModels 为 false。

兼容 macOS 15 的做法是由 SwiftUI translationTask 提供 TranslationSession。需要下载模型时，将真实的模型准备交互附着到当前可见窗口；不得假设较新 SDK 的无 UI 初始化方法在 macOS 15 上可用。

用户同意下载后调用 prepareTranslation，再翻译；取消则保留原文，不标成功。检查英文/简体中文语言对，规范化到框架要求的 Locale.Language，支持状态以系统查询结果为准。

系统管理的语言包不接入现有 ML Kit 删除页，不伪造下载进度。macOS 14 显示不支持该服务；15+ 首次准备完成后断网复测，证明设备端翻译。

## 8. 工程、隐私与交付

- 统一 macOS Podfile 与 Xcode target 的最低系统版本，新增 Swift 文件加入 Runner target。
- DebugProfile 和 Release 沙盒均配置必要的 network.client；按安全存储插件当前官方说明核对 Keychain 项。
- 调整启动页调用，macOS 不走仅移动端的平台逻辑；启动失败仍保留旧数据库和旧 JSON。
- 原生 screenshot 功能使用屏幕录制权限；只注册特定快捷键，不为此额外实现全键盘监听或自动划词。
- 更新应用内中英文隐私说明及文档，说明可选在线文字传输。公开隐私网站是独立发布目标，只提供修改清单，未经授权不部署。
- 保留既有平板适配文档及其他未提交工作，不顺带完成大屏重设计。
- 本地构建、实体设备验证、发布签名、公证和用户验收分别记录；本计划不自动推送或发布。
